# 第 13 章 分诊（信息不足）

> 目标不清时，**问清楚再动**。这章不分析，只产出"路由所需的最小信息"。

## 什么时候进这一章

- `rehub_route` 返回 `confidence=low` 或 `scenario=triage`
- `rehub_classify` 返回 `objectType=unknown`
- 用户只说一句："帮我看看这个"、"逆向一下"、"这个怎么破解"
- 目标形态不明：可能是包、可能是网页、可能是固件

## 必须问的两个问题

1. **目标是什么对象？**（先归入四类：网站/网页、App（Android/iOS/微信小程序）、软件（EXE/DLL/桌面程序）、AI 自动化（MCP/Agent 流程）；再问具体形态与文件/URL）
2. **你要的产出是什么？**（功能说明、算法/参数还原、脱壳后的代码、补丁、漏洞定位、可运行重实现、UI 原型）

补充问题（按需）：
- 有没有设备/环境限制（Windows/Linux、真机、模拟器）？
- 是否已获授权？目标是否自有？
- 有没有已知线索（关键字、接口名、错误信息）？

## 可以先生成的"零假设"事实

- `rehub_detect`：本机能做什么（这决定可行性边界）
- `rehub_classify { task, target }`：对象分类 + 静态/动态/UI 三条链路（弱输入时给澄清问题，附录 D）
- `rehub_scenarios`：可选的 15 类场景（给用户看菜单）
- 对未知文件：第 10 章 `inspect-artifact` 看清单（只读，安全）

## 不要做的事

- 不要假设"用户说的逆向=反编译 exe"
- 不要为了推进而选一个高置信度低场景
- 不要在未确认授权前分析第三方闭源软件

## 交付格式

```
已知：<用户给的信息>
缺失：目标形态 / 期望产出 / 环境 / 授权
建议：候选场景 1–2 个 + 各自需要什么输入
下一步：等用户回答后重新 rehub_route
```
