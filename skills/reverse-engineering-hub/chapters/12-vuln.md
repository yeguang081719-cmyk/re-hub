# 第 12 章 漏洞研究 / 补丁分析

> 在原生链上叠加：缓解措施 → 攻击面 → 崩溃/core → 补丁对比。用于授权范围内的安全研究。

## 什么时候进这一章

- 用户说：漏洞、0day、fuzz、崩溃、core dump、补丁改了什么、CVE 复现
- 手上有：core 文件、补丁前后两个版本、可疑二进制

## 进来先问自己 3 个问题

1. **目标是啥类型**？原生 → 第 01 章打底；托管 → 第 07 章。
2. **有 core 吗**？有就先读 core（线程/寄存器/信号/映射）。
3. **有补丁前后版本吗**？有就做函数级 diff。

## 链路（按顺序）

| 步 | 动作 | 调用 |
|---|---|---|
| 1 | 缓解措施/布局 | `mcp__rea__inspect_binary_layout`（PIE/NX/RELRO/CFG 等） |
| 2 | 攻击面 | `rehub_exec { backend:"ghidra", op:"functions" }` + 第 01 章定位解析/拷贝函数 |
| 3 | core 分析 | `mcp__rea__inspect_recorded_crash`（可选 debugger context） |
| 4 | 补丁对比 | 两份证据 → `mcp__rea__compare_functions` |
| 5 | 行为验证 | 隔离环境复现，记录输入/输出 |

## 证据要记什么

- 目标哈希、架构、缓解措施
- 可疑函数与其输入验证缺失点
- core：信号、崩溃地址、寄存器、调用栈
- 补丁差异：改了哪些函数/分支
- 复现步骤（脱敏）

## 常见坑

- **别在生产环境复现**：隔离 VM/容器。
- **core 需要匹配的二进制/库**：版本不一致会导致符号/映射错位。
- **对比要同 provider**：不同反编译器伪代码不可直接等价比较。
- **只做授权范围**：不利用、不扩散。

## 交付格式

```
目标：hash/架构/缓解
攻击面：函数/入口
崩溃：信号/地址/栈
补丁：改动的函数与语义差异
复现：最小步骤
```
