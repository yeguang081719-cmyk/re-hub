# 第 08 章 固件 / 镜像

> 先识别区域，再提取文件系统，最后把提取出的二进制交给原生链。

## 什么时候进这一章

- `.bin .img .rom .trx .chk` 等固件/镜像
- 用户说：固件分析、路由器、IoT、提取文件系统、squashfs、uboot
- 从第 10 章转来：安装包里带固件

## 进来先问自己 3 个问题

1. **要"看区域"还是"提文件"**？先区域识别，再决定是否提取（提取可能很大）。
2. **有 Linux/WSL 吗**？binwalk/unblob 在 Windows 上受限，优先 WSL。
3. **提取后要什么**？文件系统里的 ELF/脚本 → 第 01 章；配置 → 直接读。

## 链路（按顺序）

| 步 | 动作 | 调用 |
|---|---|---|
| 1 | 区域识别（binwalk） | `mcp__rea__inspect_firmware_regions` |
| 2 | 提取（unblob，Linux） | `mcp__rea__extract_firmware` / `rehub_exec { backend:"rea", op:"firmware" }` |
| 3 | 看文件系统 | 读提取目录：`etc/`、`bin/`、`lib/`、`www/` |
| 4 | 二进制深挖 | 第 01 章 |
| 5 | 脚本/配置 | 直接 read/grep |

## 证据要记什么

- 固件 SHA256、大小、厂商/型号线索
- 区域清单（offset/类型/大小）
- 提取产物路径与哈希
- 关键配置（账号密码字段需脱敏）

## 常见坑

- **Windows 上没有 binwalk/unblob**：先用 REA 的区域识别（只读），提取转 WSL。
- **多段固件/OTA 格式**：可能还有外层头，先剥头再识别。
- **提取出大量重复文件**：先看 `etc/`、`bin/`，别急着全量分析。
- **凭据**：报告里只写"存在硬编码凭据"，不贴明文。

## 交付格式

```
固件：path + sha256 + 型号线索
区域：offset/type/size 列表
文件系统：类型 + 关键路径
下一步：ELF → 第 01 章
```
