# 第 15 章 UI 逆向 / 界面结构恢复

> 目标不是"截一张图"，而是恢复**控件树 + 布局 + 资源 + 交互**，并评估能不能做成可运行原型。

## 什么时候进这一章

- 用户要"复刻这个软件的界面 / 看它的 UI 结构 / 还原对话框和菜单"；
- 需要把 UI 结构作为功能地图的一部分（菜单项、工具栏、面板）；
- UI 是 CEF/Electron 页面（可拿 DOM）或 Qt/Win32 原生界面（只能枚举控件树 + 重画）；
- 用户说：UI 逆向、界面还原、控件树、菜单结构、界面复刻、原型。

## 进来先问自己 3 个问题

1. **UI 是 Web/CEF 还是原生**？CEF/Electron → CDP 拿 DOM/CSS（可高保真）；Qt/Win32 → UIA 控件树 + 截图（重画）。
2. **要"结构"还是"像素"**？结构用 UIA/DOM；像素用截图（只作参考，不产生代码）。
3. **授权边界**：只参考结构/行为，**不拷贝**专有 CSS/字体/图片；原型要 clean-room。

## 链路（按顺序）

| 步 | 动作 | 调用 |
|---|---|---|
| 1 | 导出控件树 | `rehub_exec { backend:"uia", op:"tree", args:{ process } }` |
| 2 | 窗口截图 | `rehub_exec { backend:"uia", op:"screenshot", args:{ process, out } }` |
| 3 | 定位具体控件 | `rehub_exec { backend:"uia", op:"find", args:{ process, query:"Push" } }` |
| 4 | CEF/Electron 页面 | `mcp__rea__list_browser_targets` → `inspect_web_page`（DOM/脚本/样式） |
| 5 | 保存完整页面 | 浏览器 DevTools / SingleFile（保留 DOM+CSS+资源） |
| 6 | 分级评估 | A=HTML/CSS/JS 齐备可高保真；B=需自写交互；C=只能截图重画 |
| 7 | 做 clean-room 原型 | 自写 HTML/CSS/JS，参考结构，不拷资产 |

## 复现分级（P3 方法，可直接复用）

| 级别 | 判据 | 复现方式 |
|---|---|---|
| A | 页面自带 CSS/JS 资产 | 参考结构，自写样式与交互，可做到高保真 |
| B | 内联脚本/依赖原生桥（`su.callRuby`、`skp.sendAction`） | 提取字段/流程，自写前端 + 桥接打桩 |
| C | 无资产、纯原生绘制 | 截图 + 控件树 + 重画 |

## 证据要记什么

- 进程/窗口标题、UI 框架（Qt/CEF/Win32）
- 控件树：名称/类型/AutomationId/类名/坐标（UIA 导出 JSON）
- 截图路径；CEF 的 DOM/资源清单与页面 URL
- 复现分级与依据；原型文件路径

## 常见坑

- **Qt 控件树可能很浅**：自绘控件在 UIA 里没有语义节点，只能截图重画。
- **QML 未随包分发**：Qt Quick 应用没法拿 QML 源，只能看渲染结果。
- **CEF 需要调试端口**：没开 `--remote-debugging-port` 就拿不到 DOM；优先从程序命令行/配置找端口。
- **别直接拷贝资产**：专有 CSS/字体/图片不要进交付物；用原创样式复现布局与交互。
- **高 DPI**：截图/坐标要统一缩放（UIA 坐标是物理像素）。

## 交付格式

```
目标：进程/窗口 + UI 框架
控件树：节点数 + 关键控件（菜单/工具栏/对话框）
截图：<path>
分级：A/B/C + 理由
原型：<目录>（clean-room，说明未拷贝资产）
未知：无法恢复的控件/样式
```
